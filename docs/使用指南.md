# 使用指南：装 CLI、填契约、跑第一个任务

## 0. 先判断要不要用

| 适合 | 不适合 |
|---|---|
| 会持续迭代一个月以上的项目 | 一次性脚本 |
| 需求会反复变 | 纯探索原型 |
| 出现过多轮修改后失控 | 需求还不存在的阶段 |
| 有第二个人要看代码 | 只跑一次的 demo |

小项目只做三件事：填 `guardrails.yaml`、保留常驻卡、跑 `verify` 章节。

## 1. 安装

```bash
python -m pip install -e /path/to/ai-dev-guardrails
guardrails --version
```

不装 CLI 也可以手工复制 `pack/`，但 `lint-manual`、`brief`、`sync`、`eval-routing` 就用不了。

## 2. 初始化

```bash
guardrails init --target .
```

会复制 `pack/` 的内容：`guardrails.yaml`、`manual/`、`ARCHITECTURE.md`、`templates/`、`ci/gates.yml`。

如果目录非空，加 `--force`；它会覆盖同名文件。

## 3. 填 `guardrails.yaml`

只填五块：

```yaml
modules:
  - name: order
    path: modules/order
    layer: application
    owner: "@you"
    contract: modules/order/CONTRACT.md
    depends_on: [payment]

contracts:
  - id: http.order
    path: openapi/order.yaml
    kind: openapi

risk:
  R3: [openapi/**, migrations/**, auth/**, package.json, pyproject.toml]
  R2: [modules/**]

commands:
  affected: "npm test -- --changed"
  full: "npm test"
  typecheck: "npm run typecheck"
  lint: "npm run lint"
```

`guardrails doctor` 会检查这四个命令是否还是 `TODO`。

## 4. 裁剪手册

常驻卡 `manual/00-card.md` 只放：

- 目标一句话
- 8–10 条红线
- 路由表
- 状态与验证命令

章节在 `manual/chapters/*/SKILL.md`，上限 6 个。每个章节必须有：

- `description`：什么时候用、什么时候不要用
- `when_to_use` / `when_not_to_use`
- `token_budget`

不用的章节直接删；新增章节必须先合并/删除一个，否则 `lint-manual` 失败。

```bash
guardrails lint-manual
guardrails sync
guardrails sync --check
```

## 5. 第一个任务

```bash
mkdir -p specs/order-cancel
```

写 `specs/order-cancel/task.yaml`：

```yaml
id: order-cancel
type: feature
files:
  - modules/order/src/cancel.ts
  - openapi/order.yaml
goal: 用户可以取消未支付订单
```

然后：

```bash
guardrails brief --task specs/order-cancel
```

输出：

```text
selected: change, review, verify
risk: R3
reason: type=feature; risk=R3; R3 path: openapi/order.yaml
tokens: ~3800 / 4000
manifest: ...
```

只加载这三个章节。不要读 `manual/` 里的其他章节。

## 6. 日常节奏

| 时机 | 命令 |
|---|---|
| 任务开始 | `guardrails state init --task <id>` + `guardrails brief --task specs/<id>` |
| 每步 | `guardrails state next --task <id> --next "..." --chapter <id>` |
| 压缩后 | `guardrails state handoff --task <id>` |
| 改代码前 | `guardrails affected --diff`，只跑受影响测试 |
| red 确认后 | `guardrails test-lock --task <id>` |
| 改测试前 | `guardrails test-approve --task <id> --reason ...` |
| 提交前 | `guardrails sync --check` + `guardrails quality --diff --fail-on` |
| 合并前 | `guardrails run full` + `guardrails contract diff` + `guardrails test-check --task <id>` |
| 发布前 | `guardrails card --task <id>` + `review` 章节 |
| 每周 | `guardrails eval-routing` + `guardrails report` + `guardrails metrics report` |
| 模型/规则升级后 | `guardrails canary`；对比基线，确认没有回归 |

## 7. CI

把 `pack/ci/gates.yml` 复制到 `.github/workflows/gates.yml`。它会跑：

1. `guardrails lint-manual`
2. `guardrails sync --check`
3. `guardrails run affected|full|typecheck|lint`

契约 diff 在 `gates.yml` 里有注释示例，启用快照后取消注释。

## 8. 运行时保护（Claude Code）

`guardrails init` 会把 `.claude/settings.json` 一起复制进来。已有的项目手动合并：

```bash
guardrails doctor
```

它会：

- 在 `Edit/Write` 前拦截 `ARCHITECTURE.md`、`guardrails.yaml`、`manual/**`、`adr/**`、CI 配置。
- 在 `Bash` 前拦截 `rm -rf`、`curl | sh`、`git push --force`、`git reset --hard` 等。
- 在压缩后重新注入“先读 AGENTS.md、先跑 brief”的提示。

hook 通过 stdin 接收 JSON；`guardrails hook --event pre-tool` 在项目根目录运行。

## 9. 常见问题

**Q：章节应该写多长？**
每个章节 900–1400 tokens 以内。超预算先删例子，再把细节移到 `references/`。

**Q：为什么不能把所有流程写进 AGENTS.md？**
隐式路由会塌缩：skill 库越大，agent 越可能什么都不加载。常驻卡只放路由和红线，流程放章节。

**Q：AI 不按 `brief` 加载怎么办？**
先确认 `AGENTS.md` 被编辑器加载；仍然不遵守，就把“必须加载 manifest 章节”做成 hook/CI 检查，而不是继续在对话里强调。

**Q：小项目会不会太重？**
会。小项目只保留常驻卡 + `verify` 章节，其他章节删掉；`guardrails.yaml` 的 modules 可以先留空。

**Q：和 SpecGuard / AGT / harn 什么关系？**
SpecGuard 管 spec/test 状态机，AGT/Caper 管运行时策略，harn 给 harness 打分；本仓库只管架构契约、章节路由和契约证据。

**Q：这套东西能保证不出 bug 吗？**
不能。它保证的是：错误在合并前暴露，漂移在架构上留痕，上下文不会无限膨胀。
