# 仓库结构：顶层目录各自负责什么

本仓库同时是三样东西：一套方法论文档、一个可直接复制的模板包、一套机器校验工具。三者边界靠目录划分，不靠命名约定。

```text
ai-dev-guardrails/
├── README.md            门面：是什么、怎么快速开始、文档导航
├── AGENTS.md            本仓库维护规则（AI / 维护者入口）
├── DEVELOPMENT.md       本仓库自身架构与关键问题
├── docs/                方法论文档（带 frontmatter，受 repo-kit 检查）
│   ├── index.md         人工导航
│   ├── 使用指南.md      从安装到第一个任务（how-to）+ 完整命令速查
│   ├── 框架设计.md      三层结构、手册与任务模型、证据强度与边界（explanation）
│   ├── 仓库结构.md      本页（reference）
│   ├── _template.md     新页模板
│   └── _generated/      index / backlinks / pitfalls（生成物，勿手改）
├── pack/                可复制模板包（产物，不参与本仓库 frontmatter 检查）
│   ├── manual/          常驻卡 + 6 个章节（唯一源）
│   ├── guardrails.yaml  架构契约配置
│   ├── templates/       task / intent / spec / plan / trace 模板
│   ├── specs/           任务目录约定（raw / trace / state）
│   ├── eval/routing/    routing 基准
│   └── ci/gates.yml     真实 CI 门禁
├── schema/              内容契约与配置 schema
├── tools/guardrails/    CLI：lint / brief / sync / contract / risk / doctor / trace
└── tools/repo-kit/      文档检查与生成
```

## 三条判据

- **`docs/` 写规范，`pack/` 放产物**：规范只在 `docs/` 定义一次；`pack/` 里出现同名规则就是复制，会被 `pack/` 的 smoke test 和人工审阅挑出来。
- **`pack/manual/` 是手册的唯一源**：`guardrails sync` 由它单向生成 `AGENTS.md`、adapters 与架构规则；生成物手改会在 `sync --check` 时暴露。
- **`tools/` 是机器层**：只保结构、引用、路由、生成物与新鲜度；内容对不对靠人审。
